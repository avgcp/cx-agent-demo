### Open Questions — Verify Against Live Console / Current Docs (CAP-02)

The following two platform-capability claims are **press-only or adjacent-product claims, not confirmed in current CX Agent Studio technical docs**. They must be treated as open questions requiring live-console or Google-account-team confirmation before the implementation team scripts them as guaranteed live demo moments — they are not asserted as settled fact anywhere in this spec.

1. **Audio-to-audio voice translation for EN↔ES (US), mid-call switching.** Press coverage of the Jan 11 2026 announcement (Constellation Research, TTEC Digital, CMSWire) describes a live demo of real-time audio-to-audio translation with mid-conversation language switching across ~10 languages, "built with Google DeepMind." This specific audio-to-audio translation capability and its language list could **not** be located in the current `docs.cloud.google.com` CX Agent Studio technical reference pages (the Languages reference page documents 28 voice-language variants and automatic language detect/response-matching, but does not name audio-to-audio translation by that term). **Confirmed fallback (D-11):** the agent responds in whichever supported voice language the caller speaks, drawn from the 28 GA/Preview voice variants — English (US) and Spanish (US) are both GA — without asserting live audio-to-audio translation; any language pair outside the confirmed audio-to-audio set uses a **captioned-text fallback** instead of a spoken live-translation moment. **Action:** confirm the exact audio-to-audio language set in-console or with the Google account team before scripting EN↔ES audio-to-audio switching as a guaranteed live voice moment.
2. **Transcript → specialist summary → auto-drafted email mechanics.** Gemini Enterprise's documented adjacent capabilities — data stores (`docs.cloud.google.com/gemini/enterprise/docs/apps-data-stores`), NotebookLM Enterprise summarization, and meeting-transcript action-item extraction — are architecturally close but are **not** confirmed for this exact CX-agent-conversation-to-email workflow; no off-the-shelf "conversation → drafted email" pipeline is documented. **Action:** spec the backend claims-processing reveal as a custom-built, in-session sub-agent + Python tool chain (a simulated "reveal" screen showing a generated specialist summary and drafted customer email), and never market it to the implementation team, GTM stakeholders, or customers as an off-the-shelf Gemini Enterprise feature.

**Re-verification rule:** any capability claim used in customer-facing sales language — including both items above and every `[BUILT-IN]`-tagged row in the table — must be independently re-verified against current Google Cloud documentation (or the live CX Agent Studio console) at build time, since the platform GA'd 2026-02-04 and its docs are evolving monthly.

**Cross-reference:** both open questions above must reappear in the final Open Questions/Risks section produced in Phase 4 (AC-03) rather than being resolved and dropped here.
